# Properties and Behaviors

## What the Fiction Engine Framework Gets Right, and What It Can't Say

*Part of the Fiction Engine companion essay series.*

The fiction engine framework is a document about design decisions. It offers a single test for every rule a designer might write: does this rule produce a new fictional state, support the conditions for fictional play, or generate dead overhead? It describes failure modes. It provides a glossary. It closes with a set of criteria that let a reader assess whether a given game belongs more or less fully to the paradigm.

The framework is written as if these criteria describe properties of design documents. Apply the test to a rule and you get an answer. Run the diagnostic — remove the rule and see if the fiction keeps moving — and you learn whether the rule is load-bearing or dead weight. The framework is, in this sense, a set of tools for reading and writing design documents with precision.

The three preceding essays in this arc have been circling a complication that this framing produces without acknowledging. Essay 1 showed that accumulated fiction — the causal tissue connecting prior events to current situations to future possibilities — cannot be designed into a document; it can only be produced through play. Essay 2 showed that emergent behavior requires feedback loops between agents attending to each other's outputs, which means it requires agents. Essay 3 showed that the transparency threshold shifts with player familiarity, which means a design's relationship to the threshold is a trajectory through time rather than a fixed position in a document.

The pattern across all three is consistent: the framework's properties are conditions. The behaviors those conditions enable are a different category. And designing conditions is not the same as producing behaviors.

This essay makes that argument direct and draws its practical consequences.

---

## The Distinction

A design property is a feature of the design document that exists independently of any particular use. The number of resolution steps in a procedure is a design property. The presence or absence of a classification step between fictional intent and fictional outcome is a design property. Whether a tracked resource has a mandatory diegetic expression is a design property. All of these can be assessed by reading the document carefully, before the document has been used once.

A system behavior is a feature of the system-in-use: what happens when agents interact with the design over time. Fictional momentum is a system behavior; it exists only when players are generating and responding to accumulated fictional state, moment to moment. Emergence is a system behavior; it requires feedback loops between agents, which requires agents. Fiction-transparency — the experience of procedure operating in the background while the fiction remains primary — is a system behavior. It depends on internalization, which takes time and varies across players. The experience of consequence, of choices having weight because prior decisions have established asymmetries, is a system behavior. It depends on accumulated fiction, which only play produces.

None of these can be assessed by reading the document. They are what the document enables; they are not in the document.

The fiction engine framework describes design properties as if identifying them is equivalent to specifying system behaviors. A thin resolution procedure has the design property that could enable fiction-transparent play. Whether it does enable that play depends on the system-in-use: the players, the accumulated fiction, the learning curve, the degree to which the participants are attending to each other's outputs rather than to their own agendas. The condition and the behavior are related — the condition makes the behavior possible — but they are not the same thing, and the distinction has consequences.

---

## What the Framework Is Actually Designing

The three preceding essays arrived at a description of what the framework's rules are actually protecting, enabling, and shaping. Bringing those descriptions together makes the pattern plain.

The framework's insistence on outcomes as continuations rather than endpoints protects the accumulated causal tissue of the fiction: the structure that gives each event weight by tying it to prior decisions and opening it toward future possibilities. The framework cannot produce that tissue. Only play can. The rules create the conditions under which the tissue can form: by refusing to break the causal chain with suspended outcomes, by requiring that fictional states survive the removal of the game record, by insisting that resolutions advance rather than close. The conditions are what the designer controls. The causal tissue is what the system produces.

The framework's commitment to thin mediation preserves the feedback loops between agents that emergent behavior requires. When the procedural layer is thin enough that agents move through it rather than stopping at it, their attention flows toward each other and toward the shared fictional state. The feedback loops stay intact. But the loops are not in the design document; they are in the space between agents attending to each other's outputs. The designer creates the conditions. The agents produce the loops.

The framework's design choices — fast-internalizing rules, minimal tracking obligations, coherent resolution cycles — shape a trajectory. They determine how quickly a design reaches its stable state, how much cognitive load the entry experience imposes, whether the learning curve is short enough to complete. But the trajectory is a property of the design-in-use across time. No design document contains its own learning curve; that curve is produced by players interacting with the design across sessions.

A fiction engine is a set of conditions. The fiction is what those conditions make possible, and what agents actually produce when the conditions are in place.

## What This Changes Practically

If the framework's properties are conditions rather than guarantees, several of its evaluative stances need revision — not replacement, but precision.

**The question of paradigm membership.** The framework treats belonging to the fiction engine paradigm as a property of design documents: a game is more or less fully a fiction engine based on how well its rules satisfy the criteria. The systems framing suggests a more accurate formulation: a design belongs more or less fully to the fiction engine paradigm based on the behaviors it reliably enables in typical use. The gap between designed conditions and actual behaviors is a fact about the design's effectiveness, not a failure of the players.

A design with excellent fiction engine properties that is routinely run in ways that suppress emergent behavior — because the social agreement is absent, because the learning curve was never completed, because participants hold divergent models of what the game is doing — is less fully a fiction engine in practice than a design with modest fiction engine properties that consistently enables the relevant behaviors. This does not make the criterion irrelevant. It means the criterion is necessary but not sufficient. Designing the conditions is the designer's job; producing the behaviors is the system's job. The designer should know the difference.

**The failure modes.** The framework names four: overhead accumulation, suspended outcomes, authority drift, and orientational divergence. They are presented as design failures, things the design does wrong. The systems framing reveals something more specific: they are descriptions of how the conditions for emergent fiction can fail to produce emergent fiction. Each failure mode is a way the feedback network can degrade.

Overhead accumulation: each additional procedural demand redirects agent attention from the fiction and from each other toward the system. The feedback loops weaken not through a single rupture but through progressive attenuation. Suspended outcomes: a resolution that requires further resolution is a loop that cannot close; agents cannot respond to an outcome that has not yet been produced. Authority drift: when the mechanism that distributes narrative authority begins producing administrative prompts rather than fictional events, it stops functioning as a node in the feedback network and becomes an obstacle between fictional intent and fictional change. Orientational divergence: when participants hold different models of what the game is doing, they are effectively running feedback loops on different channels. The outputs of one agent are not inputs for another because they are not attending to the same object.

Naming these as conditions for system failure rather than intrinsic design defects clarifies what the designer's responsibility actually is. The designer cannot prevent orientational divergence by writing better rules; orientational divergence is a failure of the social agreement that underlies any game. What the designer can do is make the game's orientation legible enough that the social agreement is easier to reach and easier to maintain. That is a different design task, and it produces different design decisions.

**The social dimension.** The framework's section on the social dimension is the most honest passage in the document: "A fiction engine is a social agreement before it is a mechanical system. The rules formalize that agreement, but they cannot substitute for it." The systems framing shows precisely why this is true rather than offering it as an observation about table culture.

The social agreement is the ground-level condition for the feedback loops that everything else depends on. Mutual sensitivity between agents — participants genuinely attending to each other's outputs, treating the fiction as a common object rather than a personal stage — is not a cultural nicety that improves a game running on good procedures. It is the functional precondition for the procedures to produce emergent behavior at all. Without it, the feedback loops do not form. Without the loops, emergence is not possible regardless of how well the design conditions are specified.

Design can support the social agreement by making the game's orientation legible, by providing procedures that keep the fiction primary, by minimizing the attentional demands that pull participants toward the system and away from each other. Design cannot create the agreement. The participants create the agreement. This is the correct hierarchy, and the framework's social dimension section states it. The systems framing explains the mechanism behind the statement.

## What the Framework Gets Right

The argument so far has been a development, not a critique. The distinction between conditions and behaviors does not invalidate the framework's criteria or its analytical tools. It clarifies what those tools are actually for.

The framework's core test is correct. Rules that produce fictional change rather than overhead do create better conditions for accumulated fiction and emergent behavior than rules that generate administrative obligations without fictional output. The diagnostic — remove a rule and observe whether the fiction keeps moving — is a genuine test of whether a rule is creating conditions for the relevant system behaviors or simply adding procedural weight. The test works because design properties and system behaviors are correlated, even if they are not identical. Better conditions reliably produce better behaviors. Worse conditions reliably degrade them.

The failure modes are real. Overhead accumulation does degrade the feedback conditions. Authority drift does produce obstacles rather than conduits. The framework names these correctly even if the framing positions them as design errors rather than condition failures. The practical guidance they produce is the same either way: remove the overhead, repair the authority mechanism, address the orientational divergence. The systems framing adds precision to why this guidance is correct, not a reason to doubt it.

The framework's position-taking also holds. It correctly refuses universality: does not claim that fiction engine principles are criteria all good design should satisfy, positions itself as one paradigm among several, acknowledges that other paradigms produce experiences it is not designed to produce. This is the intellectual honesty that makes the framework worth developing. It means the framework can be pressed further, as these essays have pressed it, without the pressure reading as attack. A framework that admits its own scope can be extended at its edges without being undermined at its center.

The framework's analytical tools — the fiction/overhead distinction, the transparency threshold, the glossary terms — produce discriminating analysis when applied to real design decisions. The four-designs essay demonstrated this. The faction essay demonstrated it at the paradigm's edge. These tools work. The argument here is not that they should be replaced but that the framework's self-description — its account of what it is doing when it applies these tools — should be updated to reflect what it is actually doing.

What the framework gets right, taken seriously, is significant. The procedural commitments it describes are genuine structural conditions for the class of play it is designed to produce. A designer who builds to those conditions is building toward the relevant behaviors reliably rather than hoping for them incidentally. That is what good design does: it makes the desired behaviors probable. Recognizing that probable is not certain, and that conditions are not guarantees, does not diminish the value of getting the conditions right.

## The Honest Account

A fiction engine is a design that creates reliable conditions for emergent fiction, accumulated fictional consequence, and fiction-transparent play. It achieves this through a specific set of structural commitments: thin mediation that preserves agent-to-agent feedback loops, rules that protect the causal tissue of accumulated fictional state, a procedural layer that internalizes efficiently and operates in the background once internalized.

A fiction engine cannot guarantee emergent fiction, accumulated consequence, or fiction-transparent play. It can maximize the conditions under which these behaviors arise. The behaviors themselves are properties of the system-in-use — the design, the agents, the accumulated fiction, and the time it takes for all three to interact.

The honest account of what a fiction engine is asks more of the designer, not less. A designer who understands that they are building conditions rather than outcomes holds those conditions with precision: they know which rules are doing what kind of work, which elements of the design belong to the learning curve versus the stable state, what the social agreement requires and what the design can support without substituting for it. That precision is what allows the design commitment to remain useful under pressure rather than collapsing into dogma when the designed conditions do not produce the expected behaviors.

Concretely, it changes how a designer responds when the design is not producing the intended experience at a given table. A framework that treats design properties as system behaviors leads to one diagnosis: the game is not working because the rules are wrong, so change the rules. A framework that treats design properties as conditions leads to a more discriminating set of questions. Are the conditions present? Is the social agreement in place, or are participants holding divergent models? Has the learning curve been completed, or are procedural demands still foregrounded? Is accumulated fiction building across sessions, or is each session resetting the fiction to something near its starting state? Each question points to a different intervention, and most of them point away from the rules entirely. The designer who knows the difference between conditions and behaviors can ask the right question rather than the familiar one.

The fiction engine paradigm is a specific bet about what conditions are worth creating. Thin mediation over thick procedure. Accumulated fictional state over episodic reset. Short learning curves and efficient stable states. These are tradeoffs, and every tradeoff has costs. What is given up to stay below the transparency threshold is real: structural scaffolding, genre texture, pacing economy, the dramatic rhythm that procedural foreground can produce. A designer who makes that bet should make it deliberately, knowing what the costs are and what the conditions enable in return.

---

## The Open Question

This series has been precise about what the fiction engine paradigm's conditions enable. It has been less precise about what occurs on the other side of the tradeoffs: what system behaviors the pressure engine enables that a fiction engine cannot, whether emergence is even the right concept for what Blades in the Dark produces when running at its best, what a theory of Fate's authorial satisfaction would look like if developed with the same rigor applied here to fictional momentum.

These questions belong to a different arc, and to the theorists of the paradigms that sit across the threshold. The comparison available from the fiction engine side is necessarily limited. Other paradigms have their own structural commitments, their own conditions, their own behaviors that those conditions enable. Evaluating any of them using criteria borrowed from the fiction engine paradigm produces bad analysis, and the fiction engine framework is clear about this. The invitation here is only to apply the same rigor inward: to hold the fiction engine paradigm's own properties and behaviors with the same analytical honesty applied in the faction essay to the paradigm's limits.

What the series has done is make the fiction engine paradigm's project precise enough to see clearly against the alternatives — not as a universal standard but as a design position that knows what it is for and what it costs.

---

## Conclusion

Four essays. One arc.

The first showed that accumulated fiction — the causal tissue connecting prior events to current conditions to future possibilities — is a structural property with architectural consequences. The framework's procedural commitments protect it without naming it. Designers who build fiction engines are, among other things, building structures that allow that tissue to form.

The second showed that thin mediation creates the feedback conditions for emergent behavior. When agents attend to each other's outputs across accumulated fictional state rather than to a procedural classification layer, the feedback loops that produce emergent fiction become possible. The framework's commitment to transparency is not a stylistic preference; it is a structural condition for the class of play the paradigm is designed to produce.

The third showed that a design is a trajectory rather than a fixed object: an entry experience, a learning curve, and a stable state. The transparency threshold is player-variable, which means the design's relationship to the threshold changes as it is used. Designing the conditions includes designing the learning curve, not only the destination.

This essay showed that the conditions the framework identifies are not design properties but conditions for system behaviors. They are real, achievable, worth designing for precisely. They are properties of the system-in-use — the design, the agents, and the accumulated fiction they produce together — not guarantees inscribed in the document.

The framework correctly identifies the conditions. What the conditions produce is up to the system.
